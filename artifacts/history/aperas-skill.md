# Aperas Skill — History <a name='id/BlockNode:00CEA5MHD8001' class='aperas-anchor aperas-id'></a>

## Current Status <a name='id/BlockNode:00CEA5MHD8002' class='aperas-anchor aperas-id'></a>

The restructure has landed and has been revised through [v4.6](#id/BlockNode:00D1FMR19G001) — four minor releases atop v1, a full rewrite at v2, eleven more minor releases atop that, a role split at v3, a comprehensive operational clarity rewrite at v4, and v4.1's operational gating refinements. `skills/aperas/SKILL.md` (reached by symlink from `.agents/skills/` and `.claude/skills/`) is the base every role loads, with role-specific skills defining each role's write boundaries (`aperas-orchestrator`, `aperas-grapher`, `aperas-coder`). v4 eliminated verbose prose across all skills, formalizing upfront role gating and in-flight triage. v4.1 resolved chronic gating failures by replacing passive negative prohibitions with an imperative View Triage entry bridge, establishing dual memory/rules (`.agents/rules/aperas.md`), strictly scoping native harness artifacts to human communication, and assigning codebase-tracked meta-tasks exclusively to the Coder role. The [v4](#id/BlockNode:00CTTFT4HR001), [v4.1](#id/BlockNode:00CTTFT4HR002), [v4.2](#id/BlockNode:00CVMPRD60001), [v4.3](#id/BlockNode:00CVMPRD60002), [v4.4](#id/BlockNode:00D1DCS9YG001), [v4.5](#id/BlockNode:00D1EDPP30001) and [v4.6](#id/BlockNode:00D1FMR19G001) milestones below record what each of those releases shipped, v4.2 and v4.3 being the progressive-disclosure split and the one command form with a gating drift check, v4.4 the verification text that follows the new test structure, v4.5 that text brought to the built suites, and v4.6 the transcript path that every Work records. Open Issues remains active, alongside the still-unmeasured [trigger accuracy against a held-out split](../planning/aperas-skill.md#id/BlockNode:00CEDFKN3000A).

All three of [Task Breakdown](../planning/aperas-skill.md#id/BlockNode:00CEA5M6S8005)'s batches have now shipped: <a name='id/BlockNode:00CEA5MHD8003' class='aperas-anchor aperas-id'></a> Batch 1 (the v1 restructure itself) as v1 through v1.3, Batch 2 (the read-side and code-side rules) as v1.4, and Batch 3 (the multi-agent split) as v3 and v3.1. v2 and its v2.1–v2.11 deltas landed in between, from user reads rather than from planned batch work.

- **v4.3 — one command form, trouble recorded under its own topic, a source-reading gate that allows checking, a drift check that gates, and one minute as every role's limit on a stuck thing**: <a name='id/BlockNode:00CVMPRD60002' class='aperas-anchor aperas-id'></a> recorded as [the v4.3 delta](../discussion/aperas-skill.md#id/BlockNode:00CVJXQWNG001). The thread template and Core Thread Disciplines take any trouble under `**Friction — <topic>**` and give each Question its own topic lead-in, and the Grapher files only real tool gaps under a tool issue.
