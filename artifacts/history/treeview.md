# TreeView — History <a name='id/BlockNode:00CE1GW8T8001' class='aperas-anchor aperas-id'></a>

## Current Status <a name='id/BlockNode:00CE1GW8T8002' class='aperas-anchor aperas-id'></a>

The `Profile`/`TreeView` data model, three-tier rendering, canonical-position rule, viewcone zoom, and the `.state/` vs. tracked-mirror git split are all implemented and live-verified (against a synthetic graph exercising every scenario the design doc worked through by hand — not yet exercised against the real `AperasKG/Apeiron/` corpus, which has no live wikilinks yet to actually escape a viewcone with). `Profile`/`kg:profile` and the upward-pointing-link fix in viewcone zoom, both originally tracked as "designed, not yet implemented," are confirmed fully built — see Milestones. Three real gaps remain open: stale `TreeView.unfolds` references, a bare `aperas unfold` wrongly mutating the default view, and no raw single-node inspection command — see [Issues](../issues/treeview.md#id/BlockNode:00CE1GW638002).

## Milestones <a name='id/BlockNode:00CE1GW8T8003' class='aperas-anchor aperas-id'></a>

- `Profile`/`TreeView` data model, three-tier rendering (`aperas tree --view`, `aperas unfold`/`aperas fold`), and the canonical-position rule for a node reachable more than one way: implemented and verified against a synthetic graph.
- Checked live against the real mirror: <a name='id/BlockNode:00CE1GW8T8006' class='aperas-anchor aperas-id'></a> `AperasKG/Apeiron/BlockNode.jsonld` had 1220 `"unfolded": false` entries and zero `true` (`ArtifactNode.jsonld`: 1, also `false`) — nothing had ever actually set the old single-flag field. Dropped from `BASE_NODE_SHAPE`/`BaseNode` outright, no migration or default-view seeding needed.
- Depth-legibility marker (`'│ '` per level, replacing plain-space indent): <a name='id/BlockNode:00CE1GW8T8007' class='aperas-anchor aperas-id'></a> implemented across every indent site (`renderTreeLines`, `renderViewLines`, `renderLinkLine`, the pruned-children marker).
- Viewcone zoom (`discoverCone`/`emitNode`/`emitLinkLine`/`renderTreeWithView`): <a name='id/BlockNode:00CE1GW8T8008' class='aperas-anchor aperas-id'></a> implemented, live-verified against a synthetic graph reproducing the worked example byte-for-byte.
- `Profile`/`kg:profile` (`aperas profile create/list/remove/create-view/list-view/remove-view`): <a name='id/BlockNode:00CE1GW8T8009' class='aperas-anchor aperas-id'></a> confirmed fully implemented — `Profile`/`TreeView` classes and their shapes match the proposed schema field-for-field (`apeironNgn/node.ts`, `apeironNgn/shape.ts`), CLI wired in `kgProfile.ts`. The archived design doc's "designed, not yet implemented" status was stale by the time this was checked.
- The upward-pointing-link fix in viewcone zoom: <a name='id/BlockNode:00CE1GW8T800A' class='aperas-anchor aperas-id'></a> confirmed fully implemented, in a more general form than originally proposed — `isInCone` is checked against every cone currently active in the discovery chain (`apeironNgn/node.ts`'s `discoverCone`), not only the query's initial root apex, closing the gap for a nested cone's own upward links too, not just the root cone's.
- The canonical-position rule was loosened from an earlier, narrower version that required a node's home to separately have its own `unfolds` entry *and* a genuinely-unfolded parent — a real gap surfaced a case where a link targeting a pure breadcrumb node several levels above something genuinely unfolded would "win" and duplicate content the breadcrumb's own passthrough chain was already rendering underneath it.
- A misdesign was caught in the default-view bootstrap: <a name='id/BlockNode:00CE1GW8T800C' class='aperas-anchor aperas-id'></a> a bare `aperas unfold <ref>` with no `--view` flag was originally intended as a read-only peek, but the bootstrap convenience added later made it fall back to auto-creating and mutating the `"default"` view instead — not yet corrected in code (see [Issues](../issues/treeview.md#id/BlockNode:00CE1GW638005)).
