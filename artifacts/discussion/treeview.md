- **Depth-legibility marker: option B (`'│ '` per level) over option A (full box-drawing art)**: option A doesn't actually fix the underlying problem (depth is still `prefixWidth / perLevelWidth`, just spread across a wider glyph unit) and needs a full sibling-lookahead pass first; option B is self-describing (count the marker glyph) with no lookahead cost, at the same 2-characters-per-level width as the plain-space indent it replaces.
- **Stale `TreeView.unfolds` references: an audit/prune sweep (option 2), not just write-time validation (option 1)**: write-time validation only catches a ref that was already dead *at unfold time* — the actually-observed failure mode is a ref going stale *afterward*, through an unrelated edit or GC pass. Only a sweep that revisits existing `unfolds` entries on some cadence closes that; write-time validation is worth adding too, but as a cheap complementary check, not a substitute.
- **Upward-pointing-link gap: stop recursion at a container in the chain (option 1), not re-root to the maximal ancestor (option 2)**: option 2 is structurally cleaner in isolation but silently changes what the query is even about — `aperas tree` promising "show me the tree from *this* apex" would get violated the moment some deep node happens to link back to an ancestor. Option 1 preserves that contract exactly, degrading the link to a flat, non-recursing reference instead.
