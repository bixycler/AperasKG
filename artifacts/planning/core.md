# Core — Planning <a name='id/BlockNode:00CF23FB1G001' class='aperas-anchor aperas-id'></a>

## Implementation Plan <a name='id/BlockNode:00CF23FB1G002' class='aperas-anchor aperas-id'></a>

The plan builds the engine of [Core — Design](../design/core.md#id/BlockNode:00D24N87SR001) in plain JavaScript, in the checkout `Aperas.dev/` on branch `js-apeironngn`. The code repo `Aperas/` stays on branch `oxigraph` as the working engine the workflow uses while the new one is built. The Oxigraph-based code is kept as a frozen reference copy in `Aperas.dev/monorepo/.archive/oxigraph/` (the TerminusDB-era code is in `.archive/tdb/`), and the live code in `monorepo/packages/` is rewritten for the new engine. The plan follows the design's own boundary: first the current code moved out of the engine's directory into the shell's ([Batch 15](#id/BlockNode:00D4NBFKAG001), done), then the engine in memory (Batches 3 to 8), then the shell on disk (Batches 9 and 10), then the layers above the engine moved onto it (Batches 11 and 12), then the comparison with the Oxigraph engine (Batch 13), and last the ports (Batch 14), which no other batch needs.

- **Numbering**: <a name='id/BlockNode:00D3XQM4X0001' class='aperas-anchor aperas-id'></a> the batches continue the numbering of [Batch 1](#id/BlockNode:00CGK2C16G001) and [Batch 2](#id/BlockNode:00CGK3AH60001). [Batch 15](#id/BlockNode:00D4NBFKAG001) took the next number and came first in the order, before Batch 3. The three are done and kept in the [Archive](#id/BlockNode:00D3XP4XK0001).
- **Order**: <a name='id/BlockNode:00D3XQM4X0002' class='aperas-anchor aperas-id'></a> work that no open point blocks comes first. A batch that an open point gates builds all it can and names the gated step under **Gated by**; that step waits for the decision, and the batch is done when its other steps are and the gated step is recorded as waiting. The plan decides none of the [Open points](../design/core.md#id/BlockNode:00D24N87T000J).
- **The design is the contract, the Oxigraph code is the reference**: <a name='id/BlockNode:00D3XQM4X0003' class='aperas-anchor aperas-id'></a> [Core — Design](../design/core.md#id/BlockNode:00D24N87SR001) states rules the engine must satisfy, not a description of the old code ([Status](../design/core.md#id/BlockNode:00D24N87SR005)). Where the old code differs from a rule, the rule wins and the difference is one of the filed issues, closed by the batch that names it under **Closes**. Where the design is silent, the reference copy's behaviour is kept and the batch says so.
- **Scratch mirrors only**: <a name='id/BlockNode:00D3XQM4X8000' class='aperas-anchor aperas-id'></a> no test and no run of the new engine reads or writes the live `AperasKG/Apeiron/`; they use a fixture or a copy of the mirror under `/tmp`.
- **The code map the plan stands on**: <a name='id/BlockNode:00D3XQM4X8001' class='aperas-anchor aperas-id'></a> the graph holds the map of the store reads of the Oxigraph code, by file and line ([the map](../issues/core.md#id/BlockNode:00D1GCR1XR001)), the census of its predicates and the fact-check of the design. The structure of the callers above the store (which of `node.ts`'s 2,241 lines are the engine's, which are ingest, reconcile, render or sweeps, and which exports the commands and the service use) is in [the map of the callers above the store](../issues/core.md#id/BlockNode:00D3YFA80R001). Batch 11 stands on that map; Batches 3 to 10 do not.
- **Not in this plan**: <a name='id/BlockNode:00D3XQM4X8002' class='aperas-anchor aperas-id'></a> [Size](../design/core.md#id/BlockNode:00D24N87T000T) (what happens when the mirror outgrows memory), [Secondary index for search](../design/core.md#id/BlockNode:00D24N87T000V), [Deriving the path](../design/core.md#id/BlockNode:00D25698B0001) from the parent chain (a later refactor; the first engine keeps the stored path), the service lifecycle, which the design leaves outside itself, and the design of several graphs beyond what [Several graphs](../design/core.md#id/BlockNode:00D3CHJXK8002) states.

## Task Breakdown <a name='id/BlockNode:00CF23FB1G003' class='aperas-anchor aperas-id'></a>

Batches 3 to 14, in the order the plan gives them, [Batch 15](#id/BlockNode:00D4NBFKAG001), which came first, being done. Each batch lists its steps, the design it implements, the filed issues it closes, the open points that gate a step, and when it is done. The tests of each batch are described in the [Verification Plan](#id/BlockNode:00CF23FB1G009).

### Batch 3 — the engine's module, its meta-model and its interface <a name='id/BlockNode:00D3XQQ2VG001' class='aperas-anchor aperas-id'></a>

No behaviour yet: the boundary, the meta-model, the schemas and the oracle that the later batches are tested against. It starts once [Batch 15](#id/BlockNode:00D4NBFKAG001) has emptied `src/apeironNgn/`. Nothing here is gated.

- [ ] **1. The module and its boundary**: <a name='id/BlockNode:00D3XQQ2VG002' class='aperas-anchor aperas-id'></a> the engine is the directory `monorepo/packages/core/src/apeironNgn/` itself, with no `engine/` inside it, emptied by [Batch 15](#id/BlockNode:00D4NBFKAG001). No file of the directory imports a file system, a store library or anything of the shell: no `node:fs`, no `oxigraph`, nothing of `../shell/` and no file of `src/` outside the directory (`../*.ts`). A test reads the imports of every file of the directory and fails on any of these, so that [the boundary](../design/core.md#id/BlockNode:00D3CJFB7G001) is held by a check and not by habit.
- [ ] **2. The meta-model and the schemas**: <a name='id/BlockNode:00D3XQQ2VG003' class='aperas-anchor aperas-id'></a> the [meta-model](../design/core.md#id/BlockNode:00D4MYZ6Q0000) as types: kinds and their inheritance; for each field its [storage kind](../design/core.md#id/BlockNode:00D24N87SR00H) and its [cardinality](../design/core.md#id/BlockNode:00D24N87SR00G); the name of the reverse side of a reference or embed field; the ordered and partitioning fields; and the roles (containment, the tombstone marker, a value dropped with its target, the root kinds of the sweep and the fields it follows). The engine is constructed with a schema and closes it. A small test schema, which is not the Aperas schema, is the one the engine's tests use. The Aperas schema is written in the meta-model in `src/shell/` ([The Aperas schema](../design/core.md#id/BlockNode:00D4MZ15AR001), [Fields per class](../design/core.md#id/BlockNode:00D24N87SR00M), [the roles it assigns](../design/core.md#id/BlockNode:00D4NB5FSR001)): `children` holds containment, ordered and partitioning, with `parent` as its reverse side and not a stored field; a `Link` has `target` and `props`; an `ArtifactNode` has an optional `type`, and the hash and timestamp fields of the `ArtifactNode` and the `FolderNode` and the `kind` of a `Profile` are optional. The `orderedContainment` cardinality and the `__siblingIndex` predicate of the reference copy have no counterpart.
- [ ] **3. The interface as types**: <a name='id/BlockNode:00D3XQQ2VG004' class='aperas-anchor aperas-id'></a> the construction with a schema, and [the Reads, Writes, Persistence and Ports](../design/core.md#id/BlockNode:00D24N87T0003) as a TypeScript interface of plain strings, numbers, booleans and rows, never a term or a pair ([the index is private](../design/core.md#id/BlockNode:00D24N87SR01A)). Every read and write takes a graph argument, with one default graph until Batch 8 adds the creation and the dropping of graphs. The creation of a node, the creation and the dropping of a graph and the port operations are typed here and built by their own batches. The [Persistence](../design/core.md#id/BlockNode:00D4MZ7DZG001) group is typed with the rest: build, read out, and the ids referenced and never defined. An id is a plain string in the engine's grammar, `Kind:snowflake` or `owner:field:Kind:snowflake`, which the shell mints and the engine checks ([Ids](../design/core.md#id/BlockNode:00D24N87SR01N)). No operation marks a field partitioning, since the mark is in the schema ([Partitioning fields](../design/core.md#id/BlockNode:00D3CJDGH8001)). [Not offered](../design/core.md#id/BlockNode:00D24N87T000H) stays absent: no pattern over an unbound field, no match on the object alone, no graph position, no query language, no load or dump.
- **4. The oracle**: <a name='id/BlockNode:00D3XQQ2VR000' class='aperas-anchor aperas-id'></a> a naive implementation of the same interface, constructed with the same schema as the engine, a map of pairs with linear scans, kept for tests under `tests/support/`. Every later batch tests the engine against it with seeded random sequences of operations.
- [ ] **5. The test group**: <a name='id/BlockNode:00D3XQQ2VR001' class='aperas-anchor aperas-id'></a> `tests/engine/` under `monorepo/packages/cli/src/tests/`, standalone `<name>.test.ts` files named in a suite; the boundary test goes to `essential` and the other files to `commit`.
- **Design**: <a name='id/BlockNode:00D3XQQ2VR002' class='aperas-anchor aperas-id'></a> [The boundary](../design/core.md#id/BlockNode:00D3CJFB7G001), [The meta-model](../design/core.md#id/BlockNode:00D4MYZ6Q0000), [The engine's interface](../design/core.md#id/BlockNode:00D24N87T0003), and in the shell [The Aperas schema](../design/core.md#id/BlockNode:00D4MZ15AR001) with [Fields per class](../design/core.md#id/BlockNode:00D24N87SR00M).
- **Closes**: <a name='id/BlockNode:00D3XQQ2VR003' class='aperas-anchor aperas-id'></a> the first part of [the store is read outside the helpers](../issues/core.md#id/BlockNode:00D2536E1R001): the engine has one seam, and the rest of it closes in Batches 11 and 12. [Ingested artifacts without a `type`](../issues/core.md#id/BlockNode:00D253D680001): the Aperas schema declares the `type` of an `ArtifactNode` optional, as the design states, so such an artifact is a valid document; whether the artifacts that carry none are given one is a question of the data and stays on that issue.
- **Gated by**: <a name='id/BlockNode:00D3XQQ2VR004' class='aperas-anchor aperas-id'></a> nothing.
- **Done when**: <a name='id/BlockNode:00D3XQQ2VR005' class='aperas-anchor aperas-id'></a> the module builds, an engine is constructed with the test schema and with the Aperas schema, the boundary test passes, and `npm run verify -- --group engine` and `npm run verify -- --suite essential` pass.

### Batch 4 — records, literal fields, ids, collections and orders <a name='id/BlockNode:00D3XQQ2VR006' class='aperas-anchor aperas-id'></a>

The data model of the engine for literal and single-valued fields, before any relation exists.

- [ ] **1. Records and literal fields**: <a name='id/BlockNode:00D3XQQ2VR007' class='aperas-anchor aperas-id'></a> a record for each subject; a literal field is a plain property of the record, with no pair and no reverse side ([Literal fields are properties of the record](../design/core.md#id/BlockNode:00D39DRYB0001)); the engine reads and writes a field as the schema declares it for the node's kind ([One schema, handed in at construction](../design/core.md#id/BlockNode:00D24N87SR008)). Literals are kept as JavaScript strings, integers and booleans, so the string "1" and the number 1 differ, and a string that looks like a date stays a string ([Literal types](../design/core.md#id/BlockNode:00D24N87SR00J)).
- [ ] **2. Cardinalities**: <a name='id/BlockNode:00D3XQQ2VR008' class='aperas-anchor aperas-id'></a> `one`, `optional` and `set`, declared and never inferred from the data; the values of a set come back in no promised order; the first or only value of a single-valued field is read without a scan.
- [ ] **3. Ids**: <a name='id/BlockNode:00D3XQQ2VR009' class='aperas-anchor aperas-id'></a> [Ids](../design/core.md#id/BlockNode:00D24N87SR01N) are `Kind:snowflake`, an embedded node's id `owner:field:Kind:snowflake`, nested further for the props of a link. The kind of an id is read from its last `field:Kind:` segment, or from its prefix when it has none, and a string counts as an id only if a valid snowflake follows `Kind:`. Ids are unique across all graphs. The shell mints the ids and passes them in; the engine checks the grammar and the uniqueness of each, and refuses an id that fails the grammar.
- [ ] **4. The master map and the collections**: <a name='id/BlockNode:00D3XQQ2VR00A' class='aperas-anchor aperas-id'></a> one map from id to record, and one collection for each graph and kind holding the records themselves, in order of insertion; creating a node adds its record, deleting it removes it ([Records by kind and by graph](../design/core.md#id/BlockNode:00D24N87SR018)). The read "all ids of a kind" iterates the collection.
- [ ] **5. The orders**: <a name='id/BlockNode:00D3XQQ2VR00B' class='aperas-anchor aperas-id'></a> one comparison of ids by plain code point, the only one used to order ids; the links of a block by `position`, any other set by id, and a tie by id ([Ordering](../design/core.md#id/BlockNode:00D24N87SR01C)). A test shuffles the order of insertion and sees the same sorted output.
- [ ] **6. Existence and size**: <a name='id/BlockNode:00D3XQQ2VR00C' class='aperas-anchor aperas-id'></a> the reads "does a node exist" and "the size of the store".
- **Design**: <a name='id/BlockNode:00D3XQQ2VR00D' class='aperas-anchor aperas-id'></a> [The data model](../design/core.md#id/BlockNode:00D24N87SR00D), [Ordering](../design/core.md#id/BlockNode:00D24N87SR01C), [Identity and uniqueness](../design/core.md#id/BlockNode:00D24N87SR01M).
- **Closes**: <a name='id/BlockNode:00D3XQQ2VR00E' class='aperas-anchor aperas-id'></a> the reading of the kind of an id in [the kind of an id and an id-like string](../issues/core.md#id/BlockNode:00D2534RSG001) (the id-like string at load closes in Batch 9); the collections behind [the scans that list the ids of a kind](../issues/core.md#id/BlockNode:00D0W02KPG001) (measured in Batch 13); the comparison of [`dehydrate`'s `localeCompare`](../issues/core.md#id/BlockNode:00D39EY5B0001) (the dump closes it in Batch 9); the engine's side of [the order of a block's links](../issues/core.md#id/BlockNode:00D22ZK7C8001) (the display closes in Batch 11).
- **Gated by**: <a name='id/BlockNode:00D3XQQ2VR00F' class='aperas-anchor aperas-id'></a> [Existence](../design/core.md#id/BlockNode:00D24N87T000K) gates step 6, whether a node exists by being in a registry or by having a pair; [An invalid id and a non-canonical integer](../design/core.md#id/BlockNode:00D24N87T000S) gates whether step 1 rewrites a non-canonical integer, its id half being settled (step 3 refuses an id that fails the grammar); [A set of live ids](../design/core.md#id/BlockNode:00D24N87T000X) gates whether step 4 keeps a second collection of live ids, so step 4 keeps the one collection the design states; [The order of links without a position](../design/core.md#id/BlockNode:00D24N87T000P) gates how step 5 sorts a link with no `position` against one with it.
- **Done when**: <a name='id/BlockNode:00D3XQQ2VR00G' class='aperas-anchor aperas-id'></a> the model-based test of literal and single-valued fields holds against the oracle; a table test of ids covers a folder or an artifact named after a kind (never taken for an id); the shuffle test holds; steps 1 to 5 pass in `commit`, and step 6 is recorded as waiting.

### Batch 5 — reference and embed fields, and the reverse side <a name='id/BlockNode:00D3XQQ2VR00H' class='aperas-anchor aperas-id'></a>

- [ ] **1. Pairs and the forward side**: <a name='id/BlockNode:00D3XQQ2VR00J' class='aperas-anchor aperas-id'></a> the values of a reference or embed field are pairs on the subject's record; a write replaces the old values with the new ones; adding a pair already present changes nothing ([Writes](../design/core.md#id/BlockNode:00D24N87SR019)).
- [ ] **2. The reverse side, built on first use**: <a name='id/BlockNode:00D3XQQ2VR00K' class='aperas-anchor aperas-id'></a> the reverse of a field is built the first time the field is asked in reverse, is held on the record of each object as a set, and every later write keeps it ([Reverse, for each field, built on first use](../design/core.md#id/BlockNode:00D24N87SR017)). The reads: the subjects whose field F holds node V, their first one and their count.
- **3. Removing a node**: <a name='id/BlockNode:00D3XQQ2VR00M' class='aperas-anchor aperas-id'></a> it removes all its pairs, its record from its collection, and its entries in every reverse side that was built, and drops it from every reference field to which the schema assigns the role of a value dropped with its target (`unfolds` in the Aperas schema). Other incoming references are not removed.
- [ ] **4. Embedded nodes**: <a name='id/BlockNode:00D3XQQ2VR00N' class='aperas-anchor aperas-id'></a> an embedded node has an id that carries its owner and field, is written in its owner's record, and has no tombstone; assigning an embed field removes, recursively, every embedded node the new value does not keep ([Embedded nodes have ids and are removed outright](../design/core.md#id/BlockNode:00D24N87SR013)). Which ids the embedded nodes keep through an edit is the shell's minting and not the engine's ([Ids are stable](../design/core.md#id/BlockNode:00D24N87SR01Q)).
- [ ] **5. Links and backlinks**: <a name='id/BlockNode:00D3XQQ2VR00P' class='aperas-anchor aperas-id'></a> a `Link` has a `target` and `props`; the backlinks of a node are the `Link`s whose `target` is the node, each with its owner, read from the owner segment of the `Link`'s id and not by a scan ([Links are outgoing ports](../design/core.md#id/BlockNode:00D24N87SR011)).
- **Design**: <a name='id/BlockNode:00D3XQQ2VR00Q' class='aperas-anchor aperas-id'></a> [The index](../design/core.md#id/BlockNode:00D24N87SR015), [Writes](../design/core.md#id/BlockNode:00D24N87T000C) of the interface.
- **Closes**: <a name='id/BlockNode:00D3XQQ2VR00R' class='aperas-anchor aperas-id'></a> [`ownerOfLink` takes the first node whose `links` names a link](../issues/core.md#id/BlockNode:00D2593220001) (the owner is in the id); the reverse reads behind [the full-store scans](../issues/core.md#id/BlockNode:00D0W02KPG001) (measured in Batch 13).
- **Gated by**: <a name='id/BlockNode:00D3XQQ2VR00S' class='aperas-anchor aperas-id'></a> [Enforcement](../design/core.md#id/BlockNode:00D24N87T000M) gates the part of steps 1 and 4 that makes a write outside the shape fail, and so [`encodeDoc` and `mintEmbedded` write any key as a predicate](../issues/core.md#id/BlockNode:00D22ZWZMR001); until it is decided, a write follows the schema as the accessors of the reference copy follow the class shape, through one function where the check will sit.
- **Done when**: <a name='id/BlockNode:00D3XQQ2VR00T' class='aperas-anchor aperas-id'></a> the model-based test holds the reverse side equal to the inverse of the forward side after every operation in a random sequence, including a reverse asked after writes and one asked before; the dangling-`unfolds` and embedded-removal reproductions of the reference copy's tests pass on the engine; steps 1 to 5 pass in `commit`.

### Batch 6 — ordered fields, containment and partitioning <a name='id/BlockNode:00D3XQQ2VR00V' class='aperas-anchor aperas-id'></a>

- [ ] **1. Ordered fields**: <a name='id/BlockNode:00D3XQQ2VR00W' class='aperas-anchor aperas-id'></a> a field can be ordered; its forward side is a list on its host, so an item appears in it at most once; the port of an item is `host:item`, the reverse of the item points at that port, and the item's place is read from the host's list on demand. There is no sibling index and no order key; an insertion, a move or a removal is one splice of the list and changes no reverse entry ([Ordered fields](../design/core.md#id/BlockNode:00D255WVK0001), [Ports, the two ends of a pair](../design/core.md#id/BlockNode:00D3CJCK10001)).
- [ ] **2. Partitioning fields**: <a name='id/BlockNode:00D3XQQ2VR00X' class='aperas-anchor aperas-id'></a> a field can be marked partitioning in the schema, closed at construction, with no mark set at run time, and the engine ensures the mark: it refuses a write that would give a node a second value on the climbed side or close a cycle ([Partitioning fields](../design/core.md#id/BlockNode:00D3CJDGH8001)).
- [ ] **3. Containment**: <a name='id/BlockNode:00D3XQQ2VR00Y' class='aperas-anchor aperas-id'></a> the field to which the schema assigns containment (`children` in the Aperas schema) is ordered and partitioning; a node is in at most one container's list, containment has no cycle, the parent (`parent` in the Aperas schema) is read from the reverse of the containment field, and taking a node out of its container's list detaches it and does not delete it ([Containment](../design/core.md#id/BlockNode:00D24N87SR00Z), [Where a node's parent comes from](../design/core.md#id/BlockNode:00D2562RC8001)). Moving a node to another container is a removal from the first list and an insertion into the second, and the engine refuses the insertion while the node is still in another list.
- [ ] **4. The records follow containment**: <a name='id/BlockNode:00D3XQQ2VR00Z' class='aperas-anchor aperas-id'></a> the records are arranged in the containment tree, a node's record under its container's, with the master map beside it ([Records follow containment](../design/core.md#id/BlockNode:00D2T5P9Y8001)).
- **Design**: <a name='id/BlockNode:00D3XQQ2VR010' class='aperas-anchor aperas-id'></a> [The data model](../design/core.md#id/BlockNode:00D24N87SR00D), the interface's reads of the children in order and writes of an ordered field ([Reads](../design/core.md#id/BlockNode:00D24N87T0004), [Writes](../design/core.md#id/BlockNode:00D24N87T000C)).
- **Closes**: <a name='id/BlockNode:00D3XQQ2VR011' class='aperas-anchor aperas-id'></a> [sibling indexes are not kept dense](../issues/core.md#id/BlockNode:00D252Y7WR001) (there is no index); [a child can end with two `parent` pairs](../issues/core.md#id/BlockNode:00D2532JJR001) (the engine refuses the second container).
- **Gated by**: <a name='id/BlockNode:00D3XQQ2VR012' class='aperas-anchor aperas-id'></a> nothing.
- **Done when**: <a name='id/BlockNode:00D3XQQ2VR013' class='aperas-anchor aperas-id'></a> the model-based test of random insertions, moves (inside a list and across containers) and removals holds, after every operation, a single container for each node, no cycle, `parent` equal to the reverse of `children`, and the place of an item equal to its index in the list; the reproductions of the two closed issues are tests written first and failing on the reference copy; steps 1 to 4 pass in `commit`.

### Batch 7 — tombstones and the sweep <a name='id/BlockNode:00D3XQQ2VR014' class='aperas-anchor aperas-id'></a>

- [ ] **1. The tombstone**: <a name='id/BlockNode:00D3XQQ2VR015' class='aperas-anchor aperas-id'></a> tombstoning is the engine's operation: a tombstoned node gets the timestamp that the shell passes in (a string), in the field to which the schema assigns the tombstone marker (`tombstonedAt` in the Aperas schema), and a node is live when that field is unset; a tombstone loses all its references, its parent included, so it leaves its container's list, and it keeps its literal properties (`title`, `text`, `tombstonedAt`, and `path`, `holder` and `type` where the document has them) ([Tombstones](../design/core.md#id/BlockNode:00D24N87SR01V), [A removed node leaves its container](../design/core.md#id/BlockNode:00D24N87T000R)). The engine tombstones one node, or a subtree over containment; the rule that a removed artifact or folder tombstones its subtree is the shell's, in Batch 11 step 4.
- [ ] **2. Embedded nodes**: <a name='id/BlockNode:00D3XQQ2VR016' class='aperas-anchor aperas-id'></a> an embedded node is removed outright and never tombstoned (see Batch 5).
- [ ] **3. The sweep**: <a name='id/BlockNode:00D3XQQ2VR017' class='aperas-anchor aperas-id'></a> a mark from every live node of the root kinds that the schema marks, through the fields that it marks for the sweep (in the Aperas schema, every live `ArtifactNode` and `FolderNode`, through `children` and the targets of links), and a sweep of every tombstone left unmarked, so that a dead island of tombstones that point only at each other goes too ([The sweep](../design/core.md#id/BlockNode:00D3CHJXK8001)). When it runs is the service's.
- **Design**: <a name='id/BlockNode:00D3XQQ2VR018' class='aperas-anchor aperas-id'></a> [Tombstones](../design/core.md#id/BlockNode:00D3CHJXK8000), and the roles of [the meta-model](../design/core.md#id/BlockNode:00D4MYZ6Q0000).
- **Closes**: <a name='id/BlockNode:00D3XQQ2VR019' class='aperas-anchor aperas-id'></a> [tombstoning does not empty the node at every site](../issues/core.md#id/BlockNode:00D252W7VG001) for the nodes the engine tombstones; the tombstones that the mirror already holds (188 in `Apeiron/`, 31 in `Apeiron/.state/`) are a question of the migration of the mirror, which strips them from the tree ([Batch 9, step 6](#id/BlockNode:00D3Y3DMTR001)): 52 of them still hold `children`, `links` or `props` (40 in `Apeiron/`, all `props`; 12 in `Apeiron/.state/`), and 187 of the 188 in `Apeiron/` still carry a `parent` and stand in the `children` of their container.
- **Gated by**: <a name='id/BlockNode:00D3XQQ2VR01A' class='aperas-anchor aperas-id'></a> [Existence](../design/core.md#id/BlockNode:00D24N87T000K) gates what a node with no pair left is, after its last pair is removed.

### Batch 9 — the mirror: the format, the dump and the load <a name='id/BlockNode:00D3XQQ2VR01M' class='aperas-anchor aperas-id'></a>

- [ ] **1. The dump**: <a name='id/BlockNode:00D3XQQ2VR01N' class='aperas-anchor aperas-id'></a> the files of [The mirror](../design/core.md#id/BlockNode:00D24N87SR01W) and their [format](../design/core.md#id/BlockNode:00D24N87SR01Z): documents sorted by `@id` by code point, indented by two spaces, ending with a newline, fields in the order the schema declares, an unset field or an empty set left out except `children`, embedded entries and the values of a reference set sorted by id, integers in their canonical text. No two documents share an `@id`: the load rejects every document that carries a repeated one, keeps none of them, reports the id, and goes on ([An `@id` names one document](../design/core.md#id/BlockNode:00D24N87SR01P), [A repeated `@id` at load](../design/core.md#id/BlockNode:00D2PC3ZG8001)). ## Verification Plan <a name='id/BlockNode:00CF23FB1G009' class='aperas-anchor aperas-id'></a>

A batch is done when its tests pass at the tier it names, the entries under its **Closes** can honestly move to Resolved with the actual mechanism named, and no gated step is passed off as done. Evidence is gathered in layers, the cheapest first, and each batch names the layers it uses.

- **Layer 1, group tests**: <a name='id/BlockNode:00D3XQW6AG001' class='aperas-anchor aperas-id'></a> each batch adds its tests to a group `engine/` (or to the group of the code it moved) as standalone `<name>.test.ts` files named in a suite, per [the tiers](../design/testing.md#id/BlockNode:00D1D5F64000N). After an edit, `npm run verify -- --group <area>` and `npm run verify -- --suite essential` (5 s); before handing a batch back, and at the orchestrator's check, `npm run verify` (the `commit` suite, 60 s). If `commit` passes its budget, the work stops and is reported, for the suite needs a split. The legacy suite is never run, and `demand` ([the demand tier](../design/testing.md#id/BlockNode:00D1D5F648001)) only when the user asks for it. The tests that [step 10 of Batch 11](#id/BlockNode:00D3Z01YER001) adds for the commands and the service that no test group covers today (`runTree`, `runShow`, `runPath`, `runResolve`, `runUnfold`, `runFold`, `runZoom`, `runProfile*`, `runLinkCandidates`, `runRemove`, `runProject`, `runTrack`, `runReverseTrack`, `service.ts` and `serviceClient.ts`) are group tests of this layer, one test group for each group of the batch whose commands lack one, and each is written at the batch that requires it, Batch 11, before its group moves and not before the batch; which of them can be waived because [the differential run](#id/BlockNode:00D3XQW6AR002) covers the command is a proposal in step 10 and is not agreed.
- **Layer 2, model-based tests**: <a name='id/BlockNode:00D3XQW6AR000' class='aperas-anchor aperas-id'></a> seeded random sequences of operations on the engine and on the oracle of Batch 3, compared after every operation, with the seed printed when one fails. The operations grow with the batches: writes of literal, reference and embed fields, ordered insertions, moves and removals, tombstones, sweeps, creating and dropping a graph. The invariants held after every operation: the reverse side is the inverse of the forward side; a node is in at most one container's list and containment has no cycle; `parent` is the reverse of `children` and the place of an item is its index; a tombstone is in no list and keeps its literals; ids come back in code-point order wherever the design promises an order; no operation leaves an orphan embedded node. From Batch 14, the ports flattened equal the flat bucket.
- **Layer 3, the round trip**: <a name='id/BlockNode:00D3XQW6AR001' class='aperas-anchor aperas-id'></a> a load followed by a dump returns the files byte for byte ([The round trip is exact](../design/core.md#id/BlockNode:00D24N87T0001)), on a tiny fixture in `essential`, and on a copy of the mirror in `demand`. The mirror in the repository holds data that the design no longer states (a `predicate` on every `Link`, tombstones that still hold `children`, `links` or `props` and keep their `parent` and their place in the `children` of their container, six artifacts for `README.md` files that stand outside any folder), so the real mirror is migrated once before this layer is run on it, and the baseline of this layer on the real mirror is the migrated mirror ([the migration, Batch 9 step 6](#id/BlockNode:00D3Y3DMTR001)). In that migration the `predicate` leaves every `Link`, the tombstones are stripped from the tree and the six `README.md` artifacts are deleted (all settled); the live blocks and the artifact that have no parent are left as they stand ([settled](#id/BlockNode:00D3YSA5T8002)).
- **Layer 4, the differential run**: <a name='id/BlockNode:00D3XQW6AR002' class='aperas-anchor aperas-id'></a> the same script of commands on the reference engine and on the new one, and the dumps compared. The two designs have no mirror in common ([which mirror the differential run starts from](#id/BlockNode:00D3YG50B0002)): the reference runs on an unmigrated copy of the mirror and the new engine on the migrated copy of it, and the dumps are compared after the differences that the migration and the design make on purpose are normalised. The deliberate differences are listed and few: the migration's own changes ([Batch 9, step 6](#id/BlockNode:00D3Y3DMTR001): no `predicate` on a `Link`, the tombstones stripped from the tree, the six `README.md` artifacts and their paragraphs deleted), the order of ids by code point where `localeCompare` ordered them, the `children` order and `parent` rule of the load, the rejection of a repeated `@id`, the empty tombstone, the text of a link in `tree` and `unfold` without its predicate, the removal of `aperas link` and `aperas unlink` ([manual links are dropped](../issues/core.md#id/BlockNode:00D3WNBPPG001)), and whatever the settled open points change. Any other difference is a finding and not a pass. The harness copies both mirrors from one snapshot that includes `Apeiron/.state/`, runs every command with `</dev/null` under a timeout, and has a fixture for a `children` entry that names an id with no document ([the ghost folder](../issues/core.md#id/BlockNode:00D417WK80001)): the new engine returns it in the list of ids referenced and never defined, and what the shell does with the list is the service lifecycle.
- **Layer 5, the reproductions**: <a name='id/BlockNode:00D3XQW6AR003' class='aperas-anchor aperas-id'></a> each filed issue a batch closes has a test written from its own reproduction first, failing on the reference copy and passing on the engine, as the archived Batches were held to: a sibling gap after a move to another parent and an append, a second `parent` after a write of `children`, a repeated `@id`, a `parent` and `children` that disagree, a live and a tombstoned node at one path, a tombstone that keeps `children`.
- **Layer 6, the tools**: <a name='id/BlockNode:00D3XQW6AR004' class='aperas-anchor aperas-id'></a> `aperas check-links` and the other commands run on a copy of the mirror and agree with the reference engine's output, and `npm run build:aperas` builds a bundle that starts.
- **Layer 7, the measurements**: <a name='id/BlockNode:00D3XQW6AR005' class='aperas-anchor aperas-id'></a> Batch 13's protocol. A figure is recorded with its sample size and what it does not show, and a comparison is made only between runs on the same machine and the same copy of the mirror.
  
  - **Every timing carries its calibration**: <a name='id/BlockNode:00D457HDWG001' class='aperas-anchor aperas-id'></a> a timing is taken with a calibration beside it, the clock of the cores (`scaling_cur_freq`, read under the load) and the time of a fixed 10M-iteration Python loop (about 0.6 s at normal speed). A timing taken when the calibration is off is discarded, not corrected. A clamped CPU, held at its 400 MHz minimum, made the timings of one evening 12.7 times too slow and passed for a defect of the service ([the cost of a write](../issues/core.md#id/BlockNode:00D22Z1HJ8001)).
- **What no run does**: <a name='id/BlockNode:00D3XQW6AR006' class='aperas-anchor aperas-id'></a> read or write the live `AperasKG/Apeiron/`, restart or kill the service of `Aperas/`, or run the legacy suite.

Multi-artifact `kg:ingest` isn't transactional** ([issues/core.md](../issues/core.md#id/BlockNode:00CF1WZ4JG008)): <a name='id/BlockNode:00CGGTQ628001' class='aperas-anchor aperas-id'></a> `ingestArtifacts`/`ingestAllArtifacts` loop per file with no try/catch, so one file's failure mid-batch leaves earlier files' writes already committed with no rollback, and later files never attempted.
