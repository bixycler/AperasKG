# Webapp — Planning <a name='id/BlockNode:00CJ6V6CH0001' class='aperas-anchor aperas-id'></a>

## Implementation Plan <a name='id/BlockNode:00CJ6V6CH0002' class='aperas-anchor aperas-id'></a>

- **Phase 1 is deep read, shallow write**: <a name='id/BlockNode:00CJ6V6CH0003' class='aperas-anchor aperas-id'></a> the whole read surface plus a single in-place text edit of the current node. This is the phase the settled design describes, and its write boundary is principled rather than a scope cut — one node's own text is the only change that needs no reconciliation and no structural judgment.
- **Phase 2+ is deep write**: <a name='id/BlockNode:00CJ6V6CH0004' class='aperas-anchor aperas-id'></a> composing an intent and handing it to the Agent. Unexamined, and deliberately not foreclosed by anything in Phase 1.
- **The ordering has a rationale**: <a name='id/BlockNode:00CJ6V6CH0005' class='aperas-anchor aperas-id'></a> core extraction comes first because both the CLI and the UI consume it, and because doing it while the CLI is still the only caller keeps the byte-identical text output as a free regression test. The auth token comes next because it is independent of the listener and is the one piece whose lifecycle should be proven before anything depends on it. The listener, the tick channel and the UI follow in that order, each with a working consumer by the time it lands.

- [x] **Slice 5 — `FolderDiv` as a Solid component**: <a name='id/BlockNode:00CJ6V6CH8003' class='aperas-anchor aperas-id'></a> three slots onto three render tiers, fold and unfold via the arrow handle.
- [ ] **Slice 6 — links at two sites**: <a name='id/BlockNode:00CJ6V6CH8004' class='aperas-anchor aperas-id'></a> link text as `cite-ref`, endnote list as `cite-note`, click-through both ways, one back-reference per position, hover popover that can promote a link into `unfolds`.

- [ ] **Slice 8 — shallow write**: <a name='id/BlockNode:00CJ6V6CH8006' class='aperas-anchor aperas-id'></a> host-side `updateText(id, text)` choosing the per-type input form, link-sweep results surfaced.
- [ ] **Slice 9 — the level fields on `TreeView`**: <a name='id/BlockNode:00CMXF4WTR001' class='aperas-anchor aperas-id'></a> add `unfoldsCollapsed` and `unfoldsNoPreview` as `reference`-kind subsets of `unfolds`, extend `removeDanglingUnfolds` and `pruneStaleUnfolds` to sweep both, and correct the former's doc comment where it claims `unfolds` is the only such field. Storage only — nothing reads the fields yet — so it lands and flushes safely on its own, and every existing view stays valid with both sets empty (the default level).
- [ ] **Slice 10 — level-aware rendering in core**: <a name='id/BlockNode:00CMXF5K98001' class='aperas-anchor aperas-id'></a> split the double duty `isGenuinelyUnfolded` currently does in `buildNodeItem` (which children to walk *and* what tier they render at) so the titles level shows children title-only, and make the stashed level prune `cone.neededChildren` so a stashed node's pinned descendants stop forcing themselves into view. The pruning is the only part that touches cone *discovery* rather than tier assignment, and it deliberately breaks the standing guarantee that a pinned node is always reachable — with the knock-on that a hidden home lets a `Link` elsewhere win canonical position, which is intended. Carry the resolved level onto `RenderNodeItem` so both renderers can pick a glyph without recomputing it.
- [ ] **Slice 11 — the verbs**: <a name='id/BlockNode:00CMXF6AD8001' class='aperas-anchor aperas-id'></a> `fold` stops cascading by default, gaining `--recursive` for today's behaviour and `--stash` for the collapse that keeps the entry; `unfold` gains `--recursive`, `--no-preview` and `--unstash`. Service protocol ops and CLI flags together, since the webapp reaches them through the same ops. `fold`'s default changes for every existing caller, so `verify.ts`'s fold expectations have to be re-read rather than assumed — this is the one slice that alters behaviour already relied on.
- [ ] **Slice 12 — stem and guide on the console**: <a name='id/BlockNode:00CMXF727R001' class='aperas-anchor aperas-id'></a> rebuild the line prefix from a per-level stack of ancestor states in both `toText` and `renderTreeLines`, replacing `'│ '.repeat(depth)`, which cannot vary per column — solid `│` where an ancestor is pinned with content, `╎` where it is only a breadcrumb. `toText`'s "byte-identical to the old output by construction" doc comment stops being true and is updated rather than left to quietly go false; `verify.ts`'s tree assertions are substring-based, so they do not trip.
- [ ] **Slice 13 — glyph and stem vocabulary in the UI**: <a name='id/BlockNode:00CMXF7RG0001' class='aperas-anchor aperas-id'></a> `▶`/`▷` rotated 0°/45°/90° off the level rather than the current open/closed boolean, `●` for a pinned leaf, `…` promoted from a marker beneath the row to the control itself at a depth cut-off (with the arrow disabled there, since nothing about the node can be toggled), and `hasStem` keyed on the level instead of on `hasChildren()` — which is what removes today's inert full-height stems. The passive guide is a `repeating-linear-gradient` rather than `dotted`/`dashed`, both of which read as a merely-lighter solid line at 1px.
- [ ] **Slice 14 — gestures**: <a name='id/BlockNode:00CMXF8EYG001' class='aperas-anchor aperas-id'></a> the click/shift/ctrl/alt/alt+shift matrix wired onto the row, the arrow and the stem alike. Fixes [ctrl-click on the arrow](../issues/webapp.md#id/BlockNode:00CMWN0XDG001) as a side effect rather than as a separate errand, since that bug is exactly the uniformity this slice has to establish; the `Gutter`'s `e.stopPropagation()` has to start letting a modified click through instead of swallowing it.
- [ ] **Slice 15 — width-derived depth**: <a name='id/BlockNode:00CMXF94Z8001' class='aperas-anchor aperas-id'></a> compute `maxDepth` as `floor((width − buffer) / gutter)` in the webapp, thread it through `/api/tree`, and refetch debounced on resize. Independent of the rest and safe to land last; until it does, the cut-off state simply never occurs in the UI, exactly as today.

## Verification Plan <a name='id/BlockNode:00CJ6V6CH8007' class='aperas-anchor aperas-id'></a>

- **Slice 1 is verified by the existing suite**: <a name='id/BlockNode:00CJ6V6CH8008' class='aperas-anchor aperas-id'></a> the text render must stay byte-identical across the extraction — any diff is a regression, and no new assertion is needed to catch it.
- **Slice 2 is verified by file mode and lifetime**: <a name='id/BlockNode:00CJ6V6CH8009' class='aperas-anchor aperas-id'></a> the token file exists at 0600, its value changes across a service restart, and the old value stops being accepted.
- **Slice 3 is verified adversarially**: <a name='id/BlockNode:00CJ6V6CH800A' class='aperas-anchor aperas-id'></a> not just positively — a request with no token, with a wrong token, with a foreign `Origin`, and with a non-loopback `Host` must each be rejected; a cross-origin `fetch` from a scratch page must fail at the preflight rather than reaching a handler. An op outside the allowlist must be refused even with a valid token.
- **Slice 4 is verified by killing the service mid-stream**: <a name='id/BlockNode:00CJ6V6CH800B' class='aperas-anchor aperas-id'></a> the client must reconnect, refetch unconditionally, and — once the token from the previous run is rejected — surface the 401 state rather than retrying silently.
- **Slices 5 to 7 are verified against `aperas tree --view`**: <a name='id/BlockNode:00CJ6V6CH800C' class='aperas-anchor aperas-id'></a> the same view rendered by the UI and by the CLI must agree on tier, canonical-position verdict and hidden counts for every node, since both now read the same render tree.
- **Slice 8 is verified by round-tripping an edit**: <a name='id/BlockNode:00CJ6V6CH800D' class='aperas-anchor aperas-id'></a> text typed in the UI, stored, projected and re-parsed must come back byte-identical, and a write whose links fail to persist must be visible in the UI rather than swallowed.
