## Open Issues <a name='id/BlockNode:00CE1GW638002' class='aperas-anchor aperas-id'></a>

- **Stale `TreeView.unfolds` references have no general cleanup**: <a name='id/BlockNode:00CE1GW638004' class='aperas-anchor aperas-id'></a> `TreeView.unfold(ref)` appends with no existence check, and the only cleanup — a reactive strip-on-hard-delete — only fires at the exact moment a specific id is hard-deleted; nothing revisits an *existing* `unfolds` entry against what's currently live. Confirmed live: `.state/TreeView.jsonld`'s `default` view has named 10 `BlockNode` ids with no corresponding document at all, after unrelated reconciliation churn elsewhere reassigned/removed the blocks those ids used to name. See [Settled](../discussion/treeview.md#id/BlockNode:00CE1FFSR8006) for the chosen fix direction.
- **A bare `aperas unfold <ref>` (no `--view` flag at all) mutates the `"default"` view instead of peeking**: should be read-only — resolve and print a preview, touching no `TreeView` state — matching `aperas tree`'s own no-view default. Today it falls into the same bootstrap-and-mutate path that `aperas unfold <ref> --view` (flag present, no name) is supposed to trigger. `aperas fold`'s own no-`--view` case isn't resolved by this — folding presupposes some view's state to collapse, so a peek-equivalent doesn't obviously apply.
- **No raw single-node inspection command**: <a name='id/BlockNode:00CE1GW638006' class='aperas-anchor aperas-id'></a> `aperas tree`/`aperas backlinks --text` only ever show a rendered preview (title + truncated, anchor-stripped abstract) — right for browsing, not for verifying a stored field is exactly what's about to be pushed back via `aperas update`/`aperas insert`, or for reading a field no command shows at all (`props`, `tombstonedAt`). `aperas project --dry-run` reconstructs real markdown but only at the whole-artifact level. Today the only way to see a node's exact stored state is a direct `BlockNode.jsonld`/`ArtifactNode.jsonld` read outside the CLI entirely. Originally tracked under packaging, relocated here since it's a node-inspection gap, not a packaging one — the same gap the `aperas` skill's own item 8 independently names.
- **GFM task-list items round-trip broken**: <a name='id/BlockNode:00CE1GW638007' class='aperas-anchor aperas-id'></a> piping an ingested `- [ ] text` item stores the literal `[ ] ` marker inside the block's own `.text` *alongside* a separate `checked: false` prop, instead of stripping it — so `aperas project` re-emits `- [ ] ` as a prefix on top of the leftover `[ ] `, doubling to `- [ ] [ ] text`. Found while drafting `archive-migration`'s own Task Breakdown; parked in its discussion doc until a real home existed, now moved here.
- **`List` isn't consumed by a preceding `Heading` the way a single paragraph already is**: a heading followed by exactly one paragraph folds that paragraph into the heading's own `.text` field, no separate child block — a list in that same position always becomes a separate child block instead, even when it's the heading's only content. Found and parked the same way as the item above, now moved here.
