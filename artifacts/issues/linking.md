## Resolved <a name='--linking---issues/---resolved' class='aperas-anchor aperas-tree'></a>
- **Heading-in-list**: resolved — a block's title isn't limited to headings, which cap at H6 and don't fit an unbounded tree. Any block whose text opens with a colon-delimited lead-in term (`Term: rest of the text`) uses that term as its title; bold/`**...**` around the term is a free style choice, not part of the rule, and its `**` characters slugify like any other non-alphanumeric character if present, same as headings' `#` markers. List nesting carries unbounded depth the same way heading nesting carries bounded depth. See [Architecture](../design/linking.md#--internal-linking---addressing/---architecture). The exact rule for which colon counts as the delimiter — outside bold *and* inline code, length-capped, language-dependent — was refined after live corpus ingestion surfaced real corruption from a simpler version of it; see [Lead-In Term Detection](../design/linking.md#--internal-linking---addressing/---topology/----lead-in-term-detection).
- **`[[deep-path]]` coexistence**: not needed, at least for now — `aperas://` scheme URLs (in-app) and `#fragment`s (compatible/pre-ingestion), including an `id/<ID>` fragment form, already make an internal reference unambiguous without a `[[...]]` wrapper. See [Topology](../design/linking.md#--internal-linking---addressing/---topology).
- **"No automated rename repair"**: misdiagnosed — a rename adds an anchor rather than replacing one, so an old reference doesn't break at rename time; there's nothing to repair, only a later cleanup once it's actually safe. See [Architecture](../design/linking.md#--internal-linking---addressing/---architecture).
- **"Duplicate-slug collisions"**: misdiagnosed — a collision only happens when two blocks share an identical *full* slug-path (same heading text at the exact same tree position), a genuine authoring error, correctly a hard reject, not a case needing disambiguation logic. Reusing the same heading title at different tree positions is ordinary and never collides, since the full path includes the distinguishing ancestor segments. See [Topology](../design/linking.md#--internal-linking---addressing/---topology).
- **Every `<block-slug-path>` written so far omitted its own H1 segment.** `toPath()` (`apeironNgn/node.ts:455-471`) walks every `BlockNode` ancestor — the H1 heading included — contributing a slug segment for each, stopping only at the owning `ArtifactNode`/`FolderNode`. Every anchor and cross-reference in this concern's own docs had been computed without that leading segment (traced back to the very first `test-slugifed-path.md` validation, which never included its own H1 either) and has been corrected corpus-wide. See [Topology](../design/linking.md#--internal-linking---addressing/---topology).
- **Cross-artifact link staleness on ingestion**: resolved — an artifact whose own text doesn't change is never re-ingested on its own, so a link it couldn't resolve stayed stale even after its target came into existence elsewhere in the corpus, with no way to fix it short of hand-editing `ingestedHash` to force a re-ingest. `kg:ingest` now stashes every code a block fails to resolve on its own referring artifact, and retries every stashed code against the current graph after its main work is done, force-reingesting (without discarding reconciliation identity — see [Discussion](../discussion/linking.md#--internal-linking---addressing---discussion/---cross-artifact-link-staleness) for the `hadContent`/`bypassUnchangedCheck` distinction) any artifact where at least one now resolves. See [Workflows](../design/linking.md#--internal-linking---addressing/---workflows).
